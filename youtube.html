Overview

The Engineering Goal

Standard recommendation systems often rely on shallow metadata or user viewing history. My objective was to build a system that actually "understands" video content. By processing over 2,000 video transcripts, the goal was to create an engine capable of recommending videos based on deep semantic word-matching and contextual similarity, regardless of the original spoken language.

The Approach

I engineered a robust offline ETL pipeline to download transcripts, automatically translating Hindi content to English for unified processing. The text was chunked, converted into embeddings, and stored in a Vector Database. I built a FastAPI backend that calculates real-time vector similarity. When a user clicks or searches on the HTML/JS frontend, the engine instantly returns the Top 10 most contextually relevant videos. The system is designed to be Dockerized for scalable AWS deployment.

Technical Deep Dive

To ensure high-quality data ingestion, I built a custom data extraction pipeline for 2000 YouTube videos. A major challenge was dealing with regional content. The pipeline detects Hindi transcripts, translates them into English, and saves them locally. This creates a unified, language-agnostic dataset, ensuring that a Hindi video covering a specific tech topic can be successfully matched and recommended alongside an English video covering the same topic.

Instead of basic keyword matching, the system relies on Vector Embeddings and Retrieval-Augmented Generation (RAG) principles. The translated transcripts are chunked and embedded into a Vector Database. When a user clicks a video, the FastAPI backend takes that video's embeddings and performs a similarity calculation against the entire database, returning the 10 videos with the highest semantic transcript overlap. A manual search bar was also implemented allowing users to search the vector space directly.

# Conceptual FastAPI Endpoint for Video Recommendation @app.get("/api/recommend/{video_id}") async def get_recommendations(video_id: str): # 1. Fetch the embedded transcript for the clicked video target_embedding = vector_db.get_embedding(video_id) # 2. Perform similarity search in Vector DB (Top 10 matches) similar_videos = vector_db.similarity_search( query_embedding=target_embedding, k=10 ) return {"status": "success", "recommendations": similar_videos}

While the initial prototype was built locally, the architecture was specifically designed for cloud deployment. The FastAPI backend and Vector Database connections are being containerized using Docker to ensure environment consistency. The final deployment strategy targets AWS (e.g., EC2 or ECS), allowing the API to scale dynamically to handle high-volume recommendation requests.
